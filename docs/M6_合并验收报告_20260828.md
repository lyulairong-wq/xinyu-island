# M6 合并验收报告

> 日期：2026-08-28
> 候选分支：`feature/m6-mvp-integration`
> 验收范围：外部邀请封闭测试的代码与本地可复现运行能力

## 结论

M6 已满足**代码合并条件**：分支已包含当前 `main`，无合并冲突；邀请准入、封测开关、免费额度项目总量保护、真实模型失败不伪装为 Mock、反馈收集和 Web 受控入口均已实现并通过自动验收。

本结论不等同于批准对外发布或开始邀请外部用户。外部封测仍须完成本报告末尾列出的人工发布门槛。

## 已验收能力

- 一次性邀请码只保存哈希值，可设置有效期、使用上限和指定邮箱；兑换后绑定到单一账号。
- 可按配置要求成年声明和邀请码；可单独暂停注册或生成。
- Token 模式与“应用”入口可以在封测中关闭；模型异常或项目总额度用尽时停止生成，不冒充正常的 Mock 回复，也不扣除 Token。
- 免费模式按北京自然日执行 `3,000` Token 用户额度，并以 `20,000,000` Token 作为项目级预留/已完成总量上限。
- 反馈入口只提交用户主动填写的类别与内容，不自动附带聊天、记忆或密钥；安全风险反馈可以正常提交。
- 技能会话与普通聊天共用封测生成暂停、Token 模式关闭等控制，不能绕过总开关。

## 外部封测前仍需人工完成的发布门槛

1. 由专业人士审核面向外部用户的用户协议、隐私政策与“仅供娱乐参考”文案；现有内部封测版本不可视为外部法律审核结论。
2. 完成实际发布所需的 ICP、HTTPS、公安备案等合规与域名准备。
3. 在阿里云北京地域完成模型、密钥、网络权限及费用告警配置；确认模型不启用联网、工具调用或思维链输出。
4. 使用受控的生产 PostgreSQL，完成加密每日备份、7 天保留及一次成功恢复演练（RPO 24 小时、RTO 4 小时）。
5. 验证云侧 ¥200 硬预算/告警，以及封测运行人员的暂停、邀请码和事故响应流程。
6. 生产配置至少应启用：邀请码与成年限制，关闭 Token 模式与应用入口，允许反馈，禁止 Mock 降级，并设置项目总量 `20,000,000` 与日免费额度 `3,000`。

具体部署、暂停与恢复操作见《M6 外部封测部署与恢复运行手册》。
