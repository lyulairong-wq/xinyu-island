# 心屿模块化开发与集成策略

## 当前基线

基础架构阶段到此冻结。它提供统一 workspace、配置、安全边界、数据库迁移、认证、测试命令、健康检查和可运行的 Web/API 骨架。基础架构的占位 UI、官方联系人和人生镜像文案不代表最终产品设计。

后续功能不得直接在 `main` 上混合开发。每次只选择一个模块，完成该模块的实现与验证后，再进入跨模块合并测试。

首个产品目标节点是[最小可用版本验收标准](最小可用版本验收标准.md)定义的免费封闭测试 MVP。每个模块使用[模块需求与验收模板](模块需求与验收模板.md)立项；公开测试前必须完成[公开测试前准备清单](公开测试前准备清单.md)。

## 建议模块顺序

1. 聊天体验模块：消息引用、删除、会话管理、历史检索及对应界面交互。
2. 联系人与记忆模块：官方 AI 配置、用户 AI、每联系人长期记忆、授权与删除边界。
3. 模型与额度模块：免费模型部署接入、Token Provider、额度重置、幂等扣减与用量展示。
4. 人生镜像与主题活动模块：仅实现虚构分支体验，不提供现实决策或预测建议。
5. 账号、隐私与数据权利模块：协议展示、授权撤回、导出、删除、举报与申诉。
6. UI/视觉模块：在单独确认信息架构、视觉规范和最终文案后实施，不与业务逻辑重构混合。

## 单模块工作流

1. 从当前 `main` 创建 `feature/<module-name>` 分支。
2. 明确该模块的 API、数据模型、权限边界、错误场景和验收用例。
3. 只修改本模块及必要的共享契约；数据库变化必须新增 Prisma migration，禁止改写历史 migration。
4. 先通过模块测试，再通过 `npm.cmd run typecheck` 和相关构建。
5. 在本地 PostgreSQL 上执行真实 API 流程验证；涉及 UI 时增加浏览器 E2E 验证。
6. 模块验证通过后提交独立 Git commit，并记录验证结果。
7. 合并到集成分支后执行 `npm.cmd run verify`、迁移状态检查和跨模块关键路径测试；通过后再合入 `main`。

## 模块验收门槛

- 类型检查、模块测试和生产构建通过。
- 用户数据只能被所属用户访问；涉及删除、记忆和额度时必须覆盖权限与边界测试。
- 高风险内容仍必须经过统一安全边界，娱乐提示不得被新模块绕过。
- 迁移可在空数据库及已有开发数据库上顺序执行。
- 模块 PR/提交不得夹带未确认 UI、最终角色设定、正式协议文本或人生镜像剧情内容。

## 统一验证命令

- `npm.cmd run test:api`：API 模块测试。
- `npm.cmd run test:web`：Web 模块测试。
- `npm.cmd run test:ai`：Provider 适配测试。
- `npm.cmd run test:safety`：安全边界测试。
- `npm.cmd run verify`：全量类型检查、测试和生产构建。

数据库启动后，可用以下命令确认迁移状态：

```powershell
$env:DATABASE_URL='postgresql://xinyu:xinyu@localhost:5432/xinyu_island?schema=public'
npx.cmd prisma migrate status --schema apps/api/prisma/schema.prisma
```
