# 心屿免费封闭测试 MVP 模块路线设计

**状态：** 已确认设计，待用户审阅后生成实施计划

## 1. 目标

将心屿首个产品节点落实为面向中国大陆中文用户的免费封闭测试 MVP。该版本验证娱乐陪伴聊天的核心体验，不包含真实 Token 支付、公开注册或公开发布。

目标用户完成以下闭环：

```text
注册并同意协议
  → 登录
  → 选择官方 AI
  → 使用真实免费模型连续聊天
  → 查看历史并继续聊天
  → 管理会话记忆
  → 删除自己的聊天或记忆
```

## 2. 总体开发策略

采用“设计与工程并行规划，功能模块独立开发和测试，最后统一集成”的方式。

- 设计确认线产出 UI 与内容的交互契约，不直接实施未确认的正式页面或剧情。
- 工程确认线产出模型、额度、安全测试和封闭测试的运行规则。
- 代码开发线一次只实施一个模块；模块通过独立测试后才可进入下一模块。
- 集成阶段只组合已独立验收的模块，不承担替代模块测试的职责。

## 3. 并行规划线

### A1：聊天信息架构与主导航确认

确认聊天、联系人、应用、我的四个主入口，以及聊天首页、会话列表、联系人选择和会话设置的层级关系。

### A2：首位官方 AI 人格与内容边界确认

确认至少一名官方 AI 的名称、人格、语气、互动边界、开场方式、禁止内容和基础角色资料。开发占位人格不得进入封闭测试。

### A3：聊天关键交互状态确认

确认以下状态的出现位置、触发条件、确认方式和文案边界：

- 常驻免费/Token 状态按钮；
- 长期记忆开关；
- 免费额度耗尽；
- 模型降级、加载和失败；
- 高风险内容边界回应；
- 消息/会话/记忆删除确认；
- 首次娱乐用途提示。

### A1–A3 的阻塞规则

A1–A3 是 M2 正式聊天 UI 的强制前置条件。未确认前仅可实现后端、共享契约、自动测试和临时开发验证界面，不得开展正式聊天 UI 实现。

### B1–B4：工程运行规则确认

- B1：确认免费开源模型候选、部署方式、许可证、资源上限和成本上限。
- B2：确认免费额度数值、重置周期、请求长度、并发、冷却和超额提示规则。
- B3：建立模型安全测试集，覆盖高风险咨询、未成年人、提示注入、记忆越权和 Provider 故障。
- B4：确认封闭测试环境、测试账户、反馈渠道、问题分级和暂停条件。

M1 的最终验收依赖 B1–B3；M6 的封闭测试准入依赖 B4。

## 4. 顺序开发模块

### M0：认证与准入

**目标：** 让新用户可安全进入聊天首页。

**范围：**

- 邮箱密码注册、登录、退出和会话失效处理；
- 年龄段选择；
- 用户协议、隐私政策和娱乐提示的查看与分别同意；
- 默认免费模式、默认关闭长期记忆；
- 桌面与手机浏览器的正式准入页面和错误反馈。

**不包含：** 邮箱验证、密码找回、第三方登录、短信登录、实名认证、数据导出和账号注销。

**独立验收：** 未完成三项同意不能进入产品；刷新可恢复有效会话；失效会话安全返回登录；年龄段和同意记录可追溯；用户之间不存在数据访问交叉。

### M1：免费模型与额度

**目标：** 接入真实免费开源模型，并控制资源使用。

**范围：**

- 模型端点配置、可用性检查和调用；
- Provider 超时、异常或空回复时的 Mock 保底；
- 免费额度、重置周期、请求长度、并发和冷却限制；
- 用量记录、额度耗尽反馈和基础运行指标；
- Provider 故障、额度限制、重复请求和降级路径测试。

**不包含：** Token 充值、支付、订阅、退款和发票。

**独立验收：** 真实模型可完成中文连续对话；达到额度后不继续调用模型；Provider 不可用时正确降级；用量不重复记录。

**依赖：** B1、B2、B3，以及 M0 提供的用户身份和授权状态。

### M2：聊天体验

**目标：** 将既有聊天底座转化为已确认的沉浸式聊天体验。

**范围：**

- 正式聊天首页、官方 AI 选择和创建会话；
- 发送、等待/生成状态、历史会话、引用、删除、归档、恢复和重命名；
- 常驻免费/Token 状态控件；
- 额度、模型降级、错误、安全边界和娱乐提示；
- 会话内长期记忆开关入口。

**不包含：** 最终多 AI 讨论组体验、支付、语音和视频。

**独立验收：** 用户可从登录后进入聊天、连续免费对话、离开后恢复历史；关键状态与 A3 一致；桌面和手机浏览器均可完成主闭环。

**依赖：** A1、A2、A3、M0、M1。

### M3：联系人与记忆

**目标：** 让每个 AI 联系人成为独立且可控的陪伴对象。

**范围：**

- 官方联系人展示与首位正式 AI 配置；
- 用户私有 AI 联系人的创建、编辑和删除基础能力；
- 每联系人长期记忆的查看、保存、删除和开关；
- 敏感信息禁止自动保存和自动注入；
- 联系人、记忆和聊天删除的范围说明。

**不包含：** 用户 AI 人格版本历史、公开分享、社区和复杂关系成长机制。

**独立验收：** 不同联系人记忆不互通；关闭记忆后不注入；删除一条记忆不删除聊天；删除聊天不自动删除长期记忆；用户只能管理自己的联系人和记忆。

**依赖：** A1、A2、M0、M2。

### M4：账号、隐私与数据权利

**目标：** 让封闭测试用户可理解、控制和删除自己的数据。

**范围：**

- 我的页面的账号信息、登录会话查看和撤销；
- 修改密码；
- 协议、隐私政策和娱乐提示的版本查看；
- 聊天、记忆和账号数据删除范围说明；
- 基础举报/问题反馈入口；
- 认证限速、关键操作审计和异常处理。

**不包含：** 邮箱找回密码、实名认证、第三方登录、完整运营后台和正式数据导出文件。

**独立验收：** 用户只能查看/撤销自己的会话；修改密码后旧会话按既定规则失效；跨用户删除被拒绝；同意版本不可被普通接口篡改；登录失败限速在账号/IP 维度生效。

**依赖：** A1、M0、M2、M3。

### M5：人生镜像入口

**目标：** 提供符合娱乐定位的应用入口，不抢跑未确认剧情。

**范围：**

- 已确认的应用入口和功能说明；
- 若首个场景内容已确认，实现一个虚构场景的开始、退出、保存/删除和重玩基础流程；
- 若内容未确认，显示“即将开放”状态，不保存开发占位剧情。

**共同约束：** 明确为虚构娱乐体验；不输出现实预测或行动建议；场景数据与聊天长期记忆隔离；删除场景记录不影响聊天、联系人或额度流水。

**独立验收：** 场景数据仅归所属用户；删除只影响场景自身数据；不自动写入长期记忆；高风险输入仍经过统一安全边界。

**依赖：** A1、A3、M0、M4；正式场景实现额外依赖已确认的剧情与文案设计。

### M6：MVP 集成与封闭测试准备

**目标：** 将已独立验收的模块组合为唯一 MVP 候选版本。

**范围：**

- 执行全量 `npm.cmd run verify`；
- 验证新数据库的顺序迁移和当前数据库迁移状态；
- 联调真实免费模型、Mock 降级和免费额度限制；
- 浏览器验证注册、协议同意、登录、官方 AI、免费聊天、历史恢复、记忆控制和删除闭环；
- 验证数据隔离、安全拦截、日志脱敏和错误响应；
- 演练开发数据库备份与恢复；
- 验证封闭测试账户、反馈渠道、问题分级和暂停条件；
- 按 `docs/最小可用版本验收标准.md` 输出通过项、阻塞项和已知限制。

**通过结论：**

| 结论 | 含义 |
|---|---|
| `MVP-ready-for-closed-beta` | 所有 MVP 功能、质量、安全和前置条件通过，可进入受控邀请测试。 |
| `MVP-blocked` | 存在真实模型、数据隔离、安全规则或设计确认等阻塞问题。 |
| `MVP-conditional` | 主闭环可运行，但有已记录的低风险遗留项；必须明确关闭条件后才可继续。 |

**依赖：** A1–A3、B1–B4、M0–M5。

## 5. 所有模块的统一完成门槛

每个 M0–M5 模块均按以下顺序完成：

```text
模块需求模板确认
  → 单元/API 测试
  → 类型检查与模块构建
  → 默认 PostgreSQL 真实 API 验证
  → 浏览器 E2E（有正式 UI 时）
  → 独立 Git 提交
  → 记录已知限制
```

各模块在合并前必须通过 `npm.cmd run verify`。涉及数据结构时，必须新增 Prisma migration，禁止修改历史 migration，并验证空数据库和当前开发数据库的顺序升级。

## 6. 设计自检

- **范围：** 仅覆盖免费封闭测试 MVP；真实支付、公开发布和未确认剧情均明确排除。
- **依赖：** M2 被 A1–A3 明确阻塞；M1 被 B1–B3 明确阻塞；M6 等待全部规划线与开发线完成。
- **隔离：** 每个开发模块都有明确目标、范围、排除项、依赖和独立验收。
- **安全：** 模型、记忆、用户数据和人生镜像均继承娱乐边界、所有权和删除隔离规则。
- **无占位：** 不使用开发占位 AI 人格或人生镜像剧情作为封闭测试正式内容。
