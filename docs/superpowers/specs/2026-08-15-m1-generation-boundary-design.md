# M1 生成边界与结算收敛设计

状态：已确认设计，待用户审阅文档

## 目标

为首发中国大陆中文封闭测试版建立唯一、可测试的生成安全与结算边界，消除现有单聊、群聊、Free、Token、引用和降级路径的行为分叉。

## 已确认约束

- 首发聊天是中文单语体验；用户消息、引用消息和最终助手回复均须符合中文单语规则。
- 规则以 NFKC 规范化后的内容为准，并拒绝所有拉丁字母及其兼容/数学字母变体；数字、中文标点和 emoji 可用。
- 不合规内容不得写入生成上下文、预约额度或调用模型。
- Token 是开发模拟模式：只调用 Mock，记录模拟用量；不提供充值、真实支付、可转移余额或收费暗示。
- Free 模式继续使用本地开源模型，故障时可降级到 Mock。
- M1 是单 API 实例部署；进程内两路非 Mock 并发限制仅在该边界内成立。多实例分布式限流不属于本次实现，但必须在部署前置中记录。

## 架构

### GenerationPolicy

唯一负责内容边界的服务，提供用户消息、引用消息和模型输出的校验入口：

1. NFKC 规范化并移除不可见控制/格式分隔符。
2. 检查汉字存在、拉丁字母不存在，并覆盖 Unicode 兼容与数学字母。
3. 调用统一高风险安全策略。
4. 返回稳定的拒绝代码，不返回可被模型利用的内部细节。

引用消息必须在组装 `generationInput` 前通过同一校验；历史不合规时拒绝本次生成，绝不将其拼入提示词。

### ChatGenerationCoordinator

协调器是聊天生成的唯一入口：先校验输入和引用，再选择生成策略，随后校验输出，最后调用结算策略。单聊和群聊仅提供不同的成员集合，不复制安全、生成或结算控制流。

### SettlementStrategy

- `free`：使用已有预约机制。助手消息、生成完成状态、用量流水和免费额度修正在同一可序列化事务中提交；失败时释放预约且不遗留助手回复。
- `token_simulated`：只使用 Mock。用户消息、助手消息、模拟用量流水和模拟余额/额度变更使用同一可序列化事务；失败时整体回滚。

## 状态与失败处理

| 情形 | 行为 |
| --- | --- |
| 用户消息或引用不合规 | 拒绝；不写用户消息、不预约、不调用模型。 |
| 模型输出不合规 | 不写助手消息；Free 释放预约；Token 模拟结算回滚。 |
| Free Provider 不可用 | 仅可降级为 Mock；Mock 输出仍经 GenerationPolicy。 |
| Token 模拟 | 不访问非 Mock Provider。 |
| 事务/结算失败 | 不产生“回复已保存但用量或额度缺失”的状态。 |

## 测试与验收

- 覆盖数学 Unicode 拉丁字母、纯英文、英文夹汉字、控制符和引用历史绕过。
- 覆盖 Free/Token 模拟 × 单聊/群聊 × 正常、拦截、Mock 降级和结算失败。
- 使用可阻塞 Provider 证明单实例内最多两条非 Mock 生成可进入 Provider。
- 用 PostgreSQL 复验事务原子性及迁移状态；Docker 可用时必须执行。
- `npm.cmd run verify` 必须通过；已有安全回归不得退化。

## 非目标

- 真实 Token 充值、支付、订阅、退款和收费。
- 多实例分布式限流。
- 正式聊天 UI、官方 AI 人格或人生镜像内容。
