# 心屿（Island）竞品与架构参考分析

版本：0.1  
用途：架构设计、领域建模和功能实现参考  
原则：只借鉴公开项目的产品思路和架构经验，不直接复用代码或资源。

## 1. 调研结论

目前没有发现一个完整覆盖以下能力的开源项目：

- 聊天软件式 AI 联系人
- 官方 AI 与用户私有 AI
- 多 AI 讨论组
- 按联系人隔离的长期记忆
- 免费开源模型 + Mock 保底 + Token Provider
- 人生分支模拟
- 全年龄安全规则
- 用户协议、隐私授权和后台安全运营

因此，心屿需要组合参考不同项目的成熟部分，而不是寻找一个完整模板。

## 2. PocketRisu

项目：https://github.com/PocketRisu/PocketRisu  
许可证：GPL-3.0

### 项目定位

自托管 AI 角色聊天平台，通过 PC、平板和手机浏览器访问服务器，支持多个 AI Provider、长期记忆、备份恢复和多语言。

### 值得参考

- 服务器端持续生成，浏览器断开后可以恢复完成结果。
- 多 Provider 统一接入。
- 聊天、角色、设置和资源统一存储。
- 服务端备份和恢复。
- Lorebook 与长期记忆独立存在。
- 一个服务同时支持桌面和移动浏览器。

### 对心屿的启发

- 生成请求必须作为服务端任务管理，不能完全依赖浏览器连接。
- Provider 需要独立抽象层。
- 聊天记录和模型调用需要解耦。
- 备份和恢复应在早期数据模型中预留。
- AI 联系人配置与聊天会话应分离。

### 不直接采用

PocketRisu 更偏个人自托管和角色扮演平台，不能直接作为心屿的线上多用户产品架构。GPL-3.0 许可证也要求进行独立法律审查。

## 3. SillyTavern

项目：https://github.com/SillyTavern/SillyTavern  
角色与群聊文档：https://github.com/SillyTavern/SillyTavern-Docs/blob/main/Usage/Characters/index.md  
许可证：AGPL-3.0

### 项目定位

面向高级用户的 LLM 角色聊天前端，支持多 Provider、角色卡、群聊、Lorebook、流式回复、移动布局和插件。

### 值得参考

角色配置包括：

- 名称、人格、场景和简介
- 首次欢迎语和示例对话
- 角色备注和说话活跃度
- 标签、收藏、搜索和排序

群聊支持：

- 一对一聊天和多角色群聊
- 添加、移除角色
- 发言顺序和目标角色
- 群聊上下文
- 指定角色回复

相关记忆扩展还展示了：

- 每个 AI 角色独立记忆
- 群聊中每个角色拥有自己的记忆
- 记忆可查看、编辑和删除
- 根据语义检索相关记忆，而不是全部注入上下文
- 单聊和群聊可以统一抽象为参与者集合

### 对心屿的启发

建议形成以下领域模型：

```text
AIContact
Conversation
ConversationParticipant
Message
ContactMemory
GroupSettings
```

单聊可以视为只有一个 AI 参与者的会话，多 AI 讨论组则是多个参与者的会话。每个 AI 只读取自己的长期记忆，群聊只共享当前会话上下文。

### 不直接采用

SillyTavern 面向高级玩家，暴露大量 Prompt、模型参数和脚本能力。心屿面向普通用户，需要把复杂配置放到后台。AGPL-3.0 代码不能未经法律审查直接进入心屿线上服务。

## 4. Dream-E

项目：https://github.com/LAION-AI/Dream-E  
许可证：MIT

### 项目定位

AI 互动小说和视觉小说引擎，支持分支剧情、变量、实体、场景、存档、AI 动态生成、后台 Provider 配置和用户配额。

### 值得参考

故事可以拆分为：

- 场景节点
- 选择节点
- 变量修改
- 实体状态
- 节点连接
- 存档和恢复点

AI 生成新场景时会综合：

- 用户动作
- 故事历史
- 当前实体
- 当前变量
- 世界状态
- 时间线
- 角色关系

其服务端还包含：

- 用户认证
- 项目管理
- AI Provider 配置
- 管理后台
- 每用户额度
- 使用日志
- SSE 流式接口
- 服务端加密保存 API Key

### 对心屿的启发

人生镜像副本应使用结构化状态，而不是只保存一段 AI 文本：

```text
ScenarioTemplate
ScenarioRun
ScenarioNode
ScenarioChoice
ScenarioState
ScenarioBranch
ScenarioSnapshot
```

官方控制场景框架，AI 生成细节；用户每次选择形成节点；节点保存状态快照；用户可以回溯重玩；结果必须保持“虚构模拟，仅供娱乐”的定位。

### 不直接采用

Dream-E 偏创作者工具和视觉小说引擎，图像、音乐和语音能力超出心屿首版范围。心屿首版应先做文字分支、状态和回溯。

## 5. ChatClaw

项目：https://github.com/fastclaw-ai/chatclaw  
许可证：MIT

### 项目定位

多 Agent 聊天平台，支持单 Agent 私聊、团队群聊、AI 顺序回复、流式输出、头像和 OpenAI-compatible API。

### 值得参考

- 单 Agent 私聊和团队群聊统一存在。
- Agent 按顺序回应。
- 每个 Agent 看到完整群聊上下文。
- 支持 `@Agent` 指定角色。
- 支持流式输出和消息操作。
- 头像选择、上传和压缩独立为共享组件。
- Web UI、运行时客户端、Gateway、数据层和认证层分离。

### 对心屿的启发

多 AI 讨论组可拆分为：

```text
GroupConversation
GroupParticipant
TurnScheduler
MentionRouter
GenerationJob
GroupContext
```

`TurnScheduler` 负责参与者选择、回复顺序、`@` 路由、生成互斥、主动发言开关和免费/Token 模式计量。

### 不直接采用

ChatClaw 面向虚拟公司和任务协作，不能把工具执行、文件操作和自动任务带入心屿。其浏览器 IndexedDB 优先模式也不适合作为心屿线上产品的权威数据源；心屿应以 PostgreSQL 为权威存储。

## 6. 对心屿架构的归纳建议

### 6.1 领域边界

```text
User & Authorization
AI Contact
Conversation & Message
Multi-AI Orchestration
Contact Memory
Free/Token Provider
Quota & Usage Ledger
Safety
Scenario Engine
Theme Activity
Admin & Publishing
Audit & Observability
```

### 6.2 三个关键架构决策

1. 单聊和群聊统一采用“参与者 + 会话上下文”模型。
2. 长期记忆按“用户 × AI 联系人”隔离，讨论组只使用独立临时记忆。
3. 人生镜像副本采用结构化分支状态、事件和快照，而不是单纯保存 AI 文本。

### 6.3 Provider 设计

用户侧只看到两种模式：

- 免费模式：开源模型优先，Mock 保底。
- Token 模式：真实 Provider，按输入和输出 Token 计量。

后台内部应保留实际 Provider、模型、耗时、失败原因和降级记录，但不让内部 Provider 差异破坏用户的聊天体验。

### 6.4 安全设计启发

参考项目普遍强调模型和角色能力，但心屿需要额外建设：

- 年龄分级
- 高风险话题处理
- 角色配置安全检查
- 输入和输出双向检查
- 记忆敏感信息限制
- 管理员最小权限
- 举报、暂停、下线、回滚和申诉

## 7. 参考项目与心屿的功能映射

| 心屿模块 | 主要参考 |
|---|---|
| AI 联系人和角色配置 | SillyTavern |
| 联系人记忆隔离 | SillyTavern 记忆扩展、PocketRisu |
| 多设备 Web 服务 | PocketRisu |
| Provider 与服务端生成 | PocketRisu、Dream-E |
| Token 配额和后台管理 | Dream-E |
| 多 AI 讨论组 | ChatClaw、SillyTavern |
| 人生镜像副本 | Dream-E |
| 关系成长和沉浸感 | Soul of Waifu，仅参考体验机制 |

| 群聊流式输出 | ChatClaw |
