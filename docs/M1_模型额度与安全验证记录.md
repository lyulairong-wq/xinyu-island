## 当前限制与后续门槛

- 首发语言边界（`fix: enforce monolingual M1 chat boundary`）：M1 仅面向中国大陆中文用户。`ChatService` 在创建用户消息、预约额度或调用 Provider 之前，要求输入至少包含一个汉字，且不得包含 Unicode Latin script 字母（包括 ASCII 与非 ASCII Latin）；英文缩写和中英混写在首发阶段均不支持。纯英文、英文高风险内容加任意汉字等混合输入均返回稳定码 `GENERATION_CHINESE_ONLY_REQUIRED`，不会进入聊天持久化或模型调用。数字、中文标点与 emoji 可正常使用。
- 助手输出同样在每条持久化前执行该严格单语检查。Free 单聊、Free 群聊、Token 单聊、Token 群聊及 Mock fallback 中的任何含 Latin script 字母输出均不会写入助手消息；Free 模式会释放已预约额度，随后以稳定码 `GENERATION_OUTPUT_CHINESE_ONLY_REQUIRED` 拒绝。本边界不修改 `evaluateMessage` 对普通英文娱乐文本的通用 `allow` 语义，而是限制首发真实聊天链路。
- 全局两路限制为单进程内存信号量。真实 API 三请求练习证明请求可完成与账务不重复；黑盒 HTTP 不暴露瞬时许可计数，因此“任意时刻不超过两路”仍以网关单元测试为主要直接证据。若需更强集成证据，应在没有并行改动时使用可观测的本地兼容 provider 做独立集成测试。
- M1 仅验证本机 Qwen3-8B 与 Mock 回退；第三方免费 provider 的选择、资质审查和线上部署仍按产品基线后置。
- 上述安全修复已完成交接并提交。聊天中的联系人配置与长期记忆作为经长度限制和安全审查后的不可信数据区块注入提示词；模型输出仅在安全决策为 `allow` 时才会持久化。
- 合并阻断修复补充：英文安全规则同时检查原始与标点分词后的文本视图；免费回复将助手消息、用量流水、额度修正和生成请求完成状态放入同一序列化事务。联系人资料和长期记忆使用 Base64 JSON 的受限不可信上下文，用户数据不能闭合上下文边界。全局两路限制使用可阻塞 Provider 的活跃计数回归测试直接验证，第三条请求须等待其中一条释放后才可进入 Provider。
- M1 Task 7 的自动化验收已在稳定工作树上完成；下一步仍需进行整分支独立代码审查与合并前数据库迁移状态复核。

## Task 4 最终自动化验证（2026-08-15，Asia/Shanghai）

- 集中式 `GenerationPolicy` 的 API 回归覆盖用户输入、引用内容和助手输出三道边界；其中引用拒绝用例断言拒绝发生在用户消息写入、Free 额度预约/结算、Token 结算及 Provider/Mock 调用之前。
- Free 路径使用本地模型链路，并在本地链路不可用时降级到 Mock；Token 开发模拟不调用 Model Gateway，只使用 Mock。相关 Free 与 Token 用例都通过原子结算 API 将助手消息、用量/账户更新和生成状态置于同一事务边界。
- 非 Mock 生成的两路限制由单进程内存信号量实施。阻塞 Provider 回归证明单一服务实例中的峰值为两路；这不是多实例部署保证。
- 首发实际聊天路径仍是仅中文：包含 Unicode Latin script 的用户输入或助手输出会在持久化/Provider 前被拒绝，稳定码分别为 `GENERATION_CHINESE_ONLY_REQUIRED` 与 `GENERATION_OUTPUT_CHINESE_ONLY_REQUIRED`。
