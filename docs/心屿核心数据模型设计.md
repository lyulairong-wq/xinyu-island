# 心屿（Island）核心数据模型设计

版本：0.1  
状态：基于需求基线和技术架构的初版设计

## 1. 建模原则

- PostgreSQL 是线上业务权威数据源。
- 所有用户相关实体必须带有明确 owner 或 scope。
- 聊天删除、记忆删除和额度记录删除相互独立。
- 内容配置使用版本化，不直接覆盖已发布版本。
- 重要消耗和安全操作使用不可变流水或审计记录。
- 不把长期记忆设计成全局用户画像。

### ConsentRecord


`consentType` 包括用户协议、隐私政策、娱乐用途、远程 Provider、长期记忆、主动联系、数据改进和 Token 规则。

## 5. 记忆与关系

### ContactMemory

```text
id
userId
contactId
sourceConversationId?
sourceMessageId?
category
content
sensitivity             # non_sensitive | sensitive
confidence?
status                  # active | deleted | superseded
createdAt
updatedAt
deletedAt?
```

数据库层面必须约束 `userId + contactId` 作用域。首版不建立全局共享记忆表。

### GroupTemporaryMemory

```text
id
conversationId
sourceMessageId?
content
expiresAt?
createdAt
deletedAt?
```

讨论组临时记忆只能由当前讨论组读取。

### RelationshipState

```text
id
userId
contactId
familiarityScore
sharedExperienceCount
interactionPreferences
lastInteractionAt
resetAt?
updatedAt
```

关系状态只用于娱乐表现，不能控制退出、删除、付费或联系人替换。

## 6. Token 额度与使用流水

### QuotaBucket

```text
id
ownerUserId
kind                    # free | gift | admin_grant | paid_reserved

remainingAmount
effectiveAt
expiresAt?
resetPolicy?
sourceRef?
status
createdAt
updatedAt
```

### UsageRecord

```text
id
userId
conversationId?
messageId?
generationRequestId
mode                    # free | token
providerName?
modelName?
inputTokens
outputTokens
totalTokens
status                  # pending | committed | rolled_back | anomaly
createdAt
committedAt?
```

免费模式可以记录 Provider 和资源消耗，但不扣用户 Token。

### QuotaLedgerEntry

```text
id
userId
quotaBucketId
usageRecordId?
delta
reason
idempotencyKey
createdAt
```

额度流水不可通过删除聊天删除。扣减、回滚和管理员调整必须可追溯。

## 10. 关键关系

```text
User 1──N Conversation
User 1──N ContactMemory
User 1──N QuotaBucket
Contact 1──N ContactVersion
Conversation 1──N ConversationParticipant
Conversation 1──N Message
Contact 1──N ContactMemory per User
Conversation 1──N GroupTemporaryMemory
ScenarioTemplate 1──N ScenarioRun
ScenarioRun 1──N ScenarioBranch
ScenarioBranch 1──N ScenarioNode
GenerationRequest 1──0..1 UsageRecord
UsageRecord 1──N QuotaLedgerEntry
```

## 11. 首版数据库实现顺序

1. User、UserSession、ConsentRecord
2. Contact、ContactVersion、UserContactState
3. Conversation、ConversationParticipant、Message
4. GenerationRequest、UsageRecord
5. QuotaBucket、QuotaLedgerEntry
6. ContactMemory、RelationshipState
7. Report、SafetyResult、AuditEvent
8. ScenarioTemplate、ScenarioRun、ScenarioBranch、ScenarioNode
9. ActivityTemplate、ActivityRun

每次结构变化使用独立 Prisma migration，并在测试数据库先执行。
